# 国家投稿与反馈

2026-09-13，第二阶段。现有 Node/WebSocket 进程和 MySQL 连接池处理投稿，无新增常驻服务。协议版本 4 增量加入 `SUBMIT_CREATION` / `SUBMISSION_RESULT`，不改变棋局字段。

## 操作与数据

登录注册账号后，可在主页头像下进入“DIY新的国家卡片”，或在任意场景的设置中打开“反馈”。国家支持 1–6 个技能，类型为普通、限定、CD、觉醒；名称、触发条件、效果、CD 规则由用户填写。先预览再提交。账号从服务端认证会话取得，不信任客户端传入的身份。

服务端整理为 `schemaVersion: 1` 的 JSON：`id`、`submittedAt`、`author.accountId/username/nickname`、`design.kind`，国家对应 `design.country.name/description/skills`，反馈对应 `design.content`。技能具有 `name/type/trigger/description/cooldown`。该格式用于收集设计，不将自然语言自动编译为可执行技能，不改变现有国家规则。

先写入 MySQL `submissions` 表，再发邮件。收件人固定为 `skillludoadapter@163.com`，发件人固定为 `skillludo@163.com`。国家主题严格为 `<国家名称>技能设计`，反馈主题带提交编号。正文含账号、时间和可读内容，附件含完整 JSON；不包含登录令牌或密码。

## 部署

SMTP 为 `smtp.163.com:465`，立即建立 TLS，校验证书，授权码从 `SMTP_AUTH_CODE` 读取。参数依据 [Nodemailer SMTP 文档](https://nodemailer.com/smtp)。服务器使用 `skillludo/smtp-credentials` Secret 的同名键；`deploy/server.yaml` 和 CI receiver 通过 secretKeyRef 引用。**无需新增 GitHub Secret**，现有 CI SSH 配置继续有效，授权码不经过 CI。

已有数据库部署先以数据库管理员执行 `deploy/submissions.sql`，目标数据库 `skill_ludo`；全新部署的 `deploy/schema.sql` 和本地 `npm run db:bootstrap` 已包括此表。迁移只新增表，可重复执行，不清空账号。`deploy/network.yaml` 放行后端 TCP 465 出站，数据库仍仅供后端访问。

升级服务器上 root 所有的 `/usr/local/sbin/skillludo-ci-receiver` 为本仓库 `deploy/ci-receiver.sh`，与镜像同一次 rollout 注入环境变量引用。数据库迁移和 Secret 预先配置；之后推送 main 继续走既有 CI/CD。发布进程仍会中断进程内棋局，建议安排在无人对局时。

容器内执行 `node scripts/verify-smtp.mjs` 仅验证连接和认证，不发送邮件。错误仅显示通用说明。授权码缺失时游戏照常工作，投稿明确提示暂未配置。

## 可靠性与限制

- 同账号每分钟一次、滚动 24 小时最多 10 次；全站每小时约 100 次，最多两封并行。单份 JSON 最多 12000 UTF-8 字节，仍在原有 WebSocket 16 KiB 上限内。国家名/技能名限制 30 字，反馈最多 3000 字。
- `(user_id, id)` 主键持久化去重；同编号重复查询不再次发送。同编号内容不同会拒绝。客户端按账号与类型保存草稿和提交编号，断线重试沿用原编号。
- 状态 `SENT` 表示 SMTP 已接受，不能保证最终进收件箱；`FAILED` 为明确 SMTP 拒绝；`UNCERTAIN` 为网络异常等无法确认；`PENDING` 为处理中或进程重启前未完成。所有状态保留原始内容。
- 不自动重发不确定邮件，以免接收方重复收到。管理员可按账号与编号查询记录后处理；这版未加入自动重试队列或管理后台。若发送期间服务重启，记录可能停留在 PENDING，应先确认收件情况再人工处理。
- 邮件仅发给固定收件人，文本不执行，不支持文件路径、外链附件或任意收件人。账号和正文不输出到服务器异常日志。

## 验证

88 项后端回归通过，新增 M01–M06 覆盖表单验证、身份防伪、SMTP 失败、持久化前置、重复提交、并行限制，以及真实 WebSocket 发送期间的心跳。

`node --env-file-if-exists=.env scripts/submission-integration.mjs` 验证真实 MySQL 的账号关联、中文 JSON、去重、限流、账户隔离；仅创建并清理自身测试账号，SMTP 使用替身。CI 已加入同一检查。本机真实 MySQL 已通过。

前端 `npm run verify:submissions` 以真实鼠标、触摸及键盘验证桌面/DPR3 手机表单、下拉框、多技能编辑、预览、重复提交和旋转。测试拦截邮件请求，不发送测试邮件。另运行既有设置回归、Web 与微信构建；构建结果不代表微信真机上线验收。

## 服务器开销

2026-09-13 空闲快照：4 核服务器 CPU 约 2%，可用内存约 1828 MiB；游戏 35 MiB、网页 3 MiB、MySQL 191 MiB。8080 未监听，保留 80 端口的同源网页与 WebSocket 入口，未添加额外反向代理或框架。此快照不是新版本承载压测；k3s 迁移暂不必要，避免增加数据库和 CI 迁移风险。
